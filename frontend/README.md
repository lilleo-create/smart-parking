# Smart Parking · фронтенд

Веб-демо показывает доступность мест на трёх демопарковках рядом с выбранным адресом. Работает на локальных примерах, без сервера и камеры. Схема адаптируется к десктопу, мобильным и горизонтальным экранам.

[Исходный макет в Figma](https://www.figma.com/design/rYLLiBNcol25YBopni3pQr/smart-parking-web?node-id=0-1)

## Первый запуск

Откройте терминал в папке `frontend`. Если терминал открыт в корне репозитория, сначала выполните `cd frontend`. Все команды ниже выполняются из этой папки.

Используйте Node.js **24.11.1** с npm. Если у вас установлен nvm, команда `nvm install` выберет версию из [файла .nvmrc](.nvmrc).

```sh
npm ci
npm run dev
```

Откройте адрес из строки **Local** в терминале. Обычно это `http://localhost:5173`. Если порт занят, Vite укажет другой адрес. Чтобы остановить приложение, нажмите **Ctrl+C**. Для повторного запуска достаточно `npm run dev`.

## Демонстрация

1. Выбрать **«Войти» → «Подставить демоданные» → «Войти»**. Для ручного входа используйте логин `driver` и пароль `parking123`. Регистрация также открывает демосессию. После выхода для повторного входа используется общий тестовый профиль.
2. Ввести адрес для поиска или оставить начальную карту Москвы. Метки показывают число свободных мест.
3. Нажать на метку или название парковки в списке. Схема показывает занятость автоматически. Нажать на свободное место и выбрать «Проложить путь» до указанного номера. Если место занято или наблюдение устарело, маршрут снимается. После парковки нажать на занятое место, чтобы запомнить его. Кнопка «Моя машина» на карте возвращает к отметке. После выезда нажать «Я уехал». Отметка хранится в этом браузере.

Поиск использует Geocoder API 2ГИС с ключом `VITE_2GIS_MAP_KEY`. Текст запроса отправляется при нажатии «Найти». Выбранный на обзорной карте адрес сохраняется в текущей вкладке до выхода из демопрофиля.

## Карта и поиск адресов

Для первого запуска ключи необязательны. По умолчанию без ключей используется OpenStreetMap. Для загрузки карты и поиска адресов нужен интернет.

Если в папке `frontend` уже есть `.env.local`, отредактируйте его. При первой настройке создайте файл из [шаблона](.env.example) командой `cp -n .env.example .env.local`.

| Переменная | Назначение |
| --- | --- |
| `VITE_YANDEX_MAPS_KEY` | Публичный ключ JavaScript API для основной карты Яндекса. |
| `VITE_2GIS_MAP_KEY` | Публичный ключ 2ГИС. Geocoder API используется для поиска адресов, Raster Tiles API — для резервной карты. |

Для ключа Яндекса укажите `localhost` среди разрешённых доменов HTTP Referer, а при публикации добавьте домен сайта. После изменения ключей перезапустите `npm run dev`. [Настройка Яндекс Карт](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html) · [Получение ключа 2ГИС](https://docs.2gis.com/platform-manager/demo-key).

При первом открытии карта показывает все три парковки. Масштаб меняется колёсиком, жестами или кнопками. Кнопка «Все парковки» возвращает общий вид. При недоступности Яндекс Карт приложение использует резервную карту. Парковку также можно открыть из списка.

## Проверка на телефоне

Подключите телефон и компьютер к одной сети Wi-Fi. Остановите текущий запуск и выполните команду:

```sh
npm run dev -- --host 0.0.0.0
```

На телефоне откройте адрес из строки **Network**. Если ограничения ключа не разрешают загрузку основной карты по локальному IP, список парковок и схемы мест останутся доступны.

## Сборка и размещение на сервере

```sh
npm test
npm run build
npm run preview
```

Первая команда проверяет обновление парковок и актуальность мест. Вторая создаёт сборку в `dist/`. Третья запускает её локальный просмотр по адресу **Local** из терминала.

Для размещения на сервере скопируйте содержимое `dist/` в корень статического сайта. Настройте выдачу `index.html` для прямых ссылок вроде `/map` и `/parkings/open-lot`. Для хостингов с поддержкой `_redirects` правило уже входит в сборку. Для nginx в существующем блоке сайта используйте `location / { try_files $uri $uri/ /index.html; }`. Ключи карт подставляются при сборке, поэтому после их смены повторите `npm run build` и загрузите обновлённые файлы.

## Подключение бэкенда

Для работы с API соберите сайт с `VITE_PARKING_API=1`. Инструкции по запуску сервера и подключению Raspberry Pi есть в [README бэкенда](../backend/README.md).

В демокаталоге с фиксированными координатами Москвы без ключей карт подложка загружается одним WebP с сайта. Источник геометрии — [© OpenStreetMap, ODbL](https://www.openstreetmap.org/copyright), [выгрузка BBBike для Москвы](https://download.bbbike.org/osm/bbbike/Moscow/). Границы подложки заданы в `src/components/CityMap.vue`. Для парковок за этими границами используется обычная карта с внешней подложкой.

Типы описаны в `src/data/parking.ts`. Объект `source` в `src/data/demo.ts` реализует три асинхронные операции. Для подключения API заменить источник в слое данных. Компоненты карты и схемы читают общее состояние из `src/data/state.ts`. Возможные серверные маршруты:

| Операция | Маршрут | Результат |
| --- | --- | --- |
| listParkings | GET /api/parkings | Доступные водителю парковки с последними снимками |
| getParking | GET /api/parkings/{id} | Название, адрес, координаты въезда и массив мест. Каждое место имеет стабильный id, подпись, секцию, ряд и позицию |
| getOccupancy | GET /api/parkings/{id}/occupancy | Снимок статусов одной парковки |

В `src/data/demo.ts` параметр `layout` каждой демопарковки задаёт секции, ряды и число мест в ряду. Поле `sectionColumns` задаёт число секций в одном ряду плана. Положение секций, мест и въезда сохраняется при изменении размера экрана. Если план не помещается, его можно прокручивать по обеим осям. Сейчас используется общая схема из четырёх секций по шесть мест (24 на парковку). При настройке макета сохраняйте обозначения существующих рядов и мест, чтобы ранее сохранённые отметки и наблюдения камеры по-прежнему указывали на нужное место. Пример частичного снимка для момента проверки 10:00:05 UTC:

```json
{
  "parkingId": "open-lot",
  "observedAt": "2026-11-21T10:00:00Z",
  "validUntil": "2026-11-21T10:00:15Z",
  "statuses": { "A1": "occupied", "A2": "free", "A3": "free", "B1": "free", "B2": "occupied", "B3": "occupied" }
}
```

В 10:00:15 UTC тот же снимок становится устаревшим. До следующего наблюдения места получают состояние «Нет данных». Пропущенное место или явное значение `unknown` также исключается из числа свободных. Личная отметка хранится у водителя. Счётчики и схема берут занятость только из наблюдений: когда камера сообщит о свободном месте, оно станет доступным независимо от отметки. Устройство в дальнейшем отправляет наблюдения серверу, а веб-клиент получает уже сопоставленные идентификаторы мест.

Старые ссылки с окончанием `/drive` открывают схему той же парковки. Выпуск для CarPlay и Android Auto требует отдельных платформенных клиентов.
